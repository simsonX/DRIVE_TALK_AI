## 발견·해결한 문제

- 셸 sandbox의 DNS/기기 소켓 제한: 허용된 환경에서 필요한 빌드/기기/모델 작업을 실행했다.
- Gradle 배포본 중복 다운로드 지연: 설치된 같은 버전 Gradle로 빌드를 진행하고 재현용 wrapper는 유지했다.
- Kotlin `ai` 변수명과 패키지 참조 충돌: BuildConfig 명시적 import로 수정했다.
- JUnit runBlocking 추론 반환형 Boolean: Unit 반환형을 명시해 기기 테스트 실행을 고쳤다.
- TTS 합성 파일은 존재하지만 재생 직전에 삭제되는 오류: 취소 핸들러 중복 등록 예외가 원인이었다. 취소 처리 한 곳으로 통합 후 실제 재생 테스트가 통과했다.
- 기기 테스트와 재설치의 동시 실행 충돌: 테스트 종료를 확인하고 단독 재실행해 결과를 검증했다.
- Qwen2.5 1.5B의 잘못된 한국어/영어 교정 설명: 검증기가 결과를 거부했다. 프롬프트 분리·언어 검사·모순 검사를 추가하고 더 큰 모델을 비교했다. 실패를 가짜 성공 응답으로 대체하지 않았다.
- Pleos Vehicle 기어 메서드 deprecation 확인: 현재 앱의 안전 판단에 사용하지 않고 공식 AAOS 속성으로 전환할 후속 항목으로 기록했다.
- 개발 PC Python 3.14의 XML expat 연결 오류: XML 보고서 검사는 시스템 Python을 사용했다. 앱/AI 브리지는 해당 XML 라이브러리에 의존하지 않는다.

1. Pleos 에뮬레이터/실차에서 실제 차량 상태와 UX 제한 연동, freshness/서비스 단절 처리.
2. Pleos STT/TTS 스트리밍과 오디오 포커스, 전화·내비 실제 통합 테스트.
3. Gleo/차량 하드웨어 음성 트리거와 MediaLibraryService 탐색 트리, 차량 호스트 심사 대응.
4. Qwen 결과의 의미/번역 검증, 불확실 피드백의 보수적 처리, 더 넓은 수준별 평가 세트.
5. 여러 사용자/차량 프로필, 설정 시간 기반의 콘텐츠 준비(자동 재생 없이), 수준 간 복습 통합.
6. 차량 온디바이스 추론 런타임과 모델 크기별 지연/메모리 비교. 파인튜닝은 현 범위에서 수행하지 않는다.

## 최종 모델 선택과 시연

- 1.5B에서 실패한 동일 평가를 Qwen3 4B에서 다시 수행해 수준별 예문·회화 질문·한국어 교정 피드백 모두 성공했다. 모델은 교체 가능한 로컬 Ollama 방식, 파인튜닝 없음.
- 회화 질문 반복을 발견하여 프롬프트에 선택된 턴의 주제를 직접 넣도록 수정했다. 3개 턴 질문이 서로 다른 것을 실제 모델로 검증했다.
- 앱에서 실제 Qwen 생성 문장을 들어 보고 HARD로 평가한 뒤 퇴근 복습 첫 항목에 반영되는 것을 확인했다.
- Android 단위 8개, 기기 4개, 서버 11개 테스트 통과. lint 오류 0. 실제 APK와 시연 증거를 남겼다.

## 문장 개수 기반 학습으로 변경

- 사용자 피드백에 따라 분 단위 종료를 없애고 3·5·10·15개 문장 선택으로 바꿨다. 시간은 학습 통계에만 남긴다.
- 유한한 서로 다른 문장 큐를 사용하며 선택량을 마치면 자동 종료한다. 같은 문장 반복은 완료 개수를 늘리지 않고, 건너뛰기는 청취로 인정하지 않는다.
- TTS 속도를 0.88에서 0.78로 낮췄다. 언어 사이 2초 PCM 쉼, 다음 문장 전 기본 8초(5·8·12초 설정)를 추가했다.
- 준비 중과 문장 사이 대기에서도 일시정지·재개가 동작한다. 기존 분 설정은 문장 개수로 잘못 해석하지 않고 새 설정 기본값 5개를 사용한다.

## Qwen 재생성 수정

- 실제 동일 조건 3회 요청에서 1회차와 3회차가 같은 문장을 반환하는 현상을 확인했다. 버튼이 한 번만 동작하는 것처럼 보일 수 있었다.
- 요청에 최근 영어 문장 최대 6개를 포함하고 서버·앱에서 정규화한 동일 문장을 거부한다. 생성 프롬프트의 다양성을 높이고 중복 응답은 서버에서 한 번 재시도한다.
- 생성 중 상태를 작업 시작 전에 설정해 빠른 중복 탭을 방지한다. 취소된 이전 작업이 새 작업의 버튼 상태를 덮어쓰지 않도록 요청 버전을 검사한다.
- 생성 횟수와 **다른 예문 생성** 버튼을 표시한다. 실패/시간 초과 후에는 기존 문장을 유지하고 다시 시도할 수 있다.
- 클라이언트/서버의 중첩 재시도를 없애 긴 대기를 줄이고 응답 대기를 제한했다.
